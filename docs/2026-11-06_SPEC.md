# PR 自動レビュー 仕様

作成日: 2026-11-06

## 目的

自分または所属チームにレビュー依頼が来た PR を、人手を介さずに Claude が事前にレビューし、結果を自分専用のローカルのページで読めるようにする。ページから PR について Claude に質問もできる。PR には一切書き込まない。

## 決定事項

| 項目 | 内容 |
|---|---|
| 実行場所 | Mac の launchd + `claude -p`（クラウドのルーチンは使わない。理由は下記） |
| 起動 | launchd で 15 分ごと。設定した曜日と時間帯（既定は月〜金の 9〜20 時）だけ処理する。多重起動はしない |
| 対象 | 設定した organization 全体の `review-requested:<自分>`（直接の依頼とチーム経由の両方）。除外なし |
| 再レビュー | head の SHA が変わったら全体をレビューし直す。前の版は折りたたんで残す（最大 5 版） |
| 再依頼 | 自分がレビューを出すと GitHub は依頼を外す（チーム経由の依頼も外れる）。その後また依頼中になったら再依頼とみなし、push が無くてもレビューし直す。「確認済み」も外す |
| 自分の指摘 | 自分が GitHub に書いたレビュー・行コメントと、それへの返信を渡し、指摘ごとの対応状況（未対応 / 一部対応 / 判断できない / 返信で回答 / 対応済み）を出す。ここで扱った指摘は新しい指摘に重ねない |
| レビュー観点 | 設定で指定したファイル（`PR_REVIEW_RULE_FILES`）と、リポジトリの `CLAUDE.md` / `AGENTS.md` / リンターの設定。観点の優先順位などは、自分用の追加の指示（`PR_REVIEW_EXTRA_PROMPT`）に書く |
| 結果の形式 | 概要は 1〜3 行の箇条書き。指摘は重要な順に `[must]` / `[q]` / `[imo]` / `[nit]` と観点の記号（あれば）を付け、理由 1〜2 文と提案 1 文にする。確認ポイントは最大 3 件、良い点は最大 2 件 |
| 出力 | `out/index.html`（ローカル。共有しない） |
| 質問 | `lib/server.py` が `127.0.0.1:8765` でページを配信し、ページから Claude に質問できる。質問欄は各カードの下と、指摘ごとの「これについて聞く」。会話は push ごとに 1 つ（`--resume` で続ける）。答えは書きながら表示する。サーバーは launchd で常駐させる |
| 量の上限 | 1 回の実行で最大 5 件。差分が 3,000 行を超える PR は要約と注意点を中心にする |
| 失敗時 | ページにエラーとして出し、次の回にやり直す。同じ SHA で 3 回失敗したら止める |
| 通知 | なし（ページだけ） |

## 構成

処理は 3 段に分かれる。

1. **取得**（`lib/pr_review.py`）: 自分の `gh` で依頼中の PR を探し、本文・コミット・差分・head 時点のファイル一式（GitHub の tarball）を作業ディレクトリに展開する。`gh api` は常に `-X GET` で呼ぶ。手元の clone には触れない。
2. **レビュー**（`claude -p`）: 作業ディレクトリをカレントにして、次の制限で動かす。
   - `--tools "Read,Grep,Glob"`: ファイルを読むツールだけにする（Bash・Edit・WebFetch などは存在しない）
   - `--strict-mcp-config`: MCP サーバー・コネクタを使わせない
   - `--setting-sources project`: 自分の `~/.claude/settings.json` の許可設定や hooks を持ち込まない。作業ディレクトリの `.claude/settings.json` だけを読む
   - `--permission-mode dontAsk`: 事前に許可されていない操作は確認なしで拒否する。作業ディレクトリの外の読み取りは拒否される
   - `--json-schema`: 結果を決まった形の JSON で受け取る
3. **生成**（`lib/pr_review.py`）: JSON から `out/index.html` を作り直す。PR 由来の文字列はすべて `textContent` で描画する。

GitHub の認証情報を使うのは 1 だけで、PR に書き込む処理はどこにも無い。2 の Claude は GitHub の権限もツールも持たないので、PR の本文などに悪意のある指示が紛れ込んでいても、影響はレビュー文の内容にとどまる。質問への回答も同じ制限で動かす。

## 置き場所と macOS のプライバシー保護（TCC）

| もの | 場所 | 理由 |
|---|---|---|
| コード | リポジトリ（どこに置いてもよい） | |
| 設定（`config/env` と自分用の追加の指示） | リポジトリの中。`env.example` 以外は `.gitignore` で除外 | 組織や個人に固有の値を含む |
| 記録・結果ページ（`data/`・`out/`） | リポジトリの中。`.gitignore` で除外 | 非公開のコードや PR の中身を含む |
| Claude の作業ディレクトリ | `~/Library/Caches/pr-review-routine` | TCC の対象外。`claude` に `~/Desktop` などを読む許可を与えずに済む |
| ログ | `~/Library/Logs/pr-review-routine` | |

確認済みの挙動（macOS 27.2）:

- launchd から起動した bash は、`~/Desktop` 配下を読めない（`Operation not permitted`）。許可を求めるダイアログも出ない。
- 許可は親プロセスから引き継がれず、プロセスごとに判定される（bash が拒否されても、その子の python3 は自分の許可で読めた）。
- そのため launchd からは python3 を直接起動し、Claude の作業ディレクトリは TCC の対象外に置く。リポジトリを TCC の対象のフォルダに置く場合は、python3 にだけ許可が要る。

## 確認済みの前提（2026-11-06）

- `review-requested:<login>` は、直接の依頼とチーム経由の依頼の両方を返す。
- チーム経由の依頼は、そのチームのメンバーがレビューを出すと外れる。再依頼はレビューした本人宛てに来る。
- 上記 2 の制限で、作業ディレクトリの中は Read でき、外の Read と Glob は `permission_denials` として拒否される（Claude Code 2.1.318）。
- `--json-schema` の結果は出力 JSON の `structured_output` に入る。
- `--resume` は同じ作業ディレクトリでのみ会話を続けられる（会話は作業ディレクトリごとに保存される）。

## 再依頼の判定

レビューを出すと依頼が外れることを使う。

- 前回の実行で「依頼が外れた」になっていた PR が、また依頼中になった
- 前回の実行より後に自分がレビューを出しているのに、まだ依頼中になっている（15 分の間にレビューと再依頼が両方起きた場合）

検索結果は少し遅れて更新されるため、レビューを出した直後に古い結果を拾うことがある。そのため後者は、依頼先（`requested_reviewers`）に実際に自分かチームが入っているときだけ判定し、入っていないときは自分のレビュー時刻も更新しない。

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| クラウドのルーチン（Claude Code の scheduled tasks） | 公式の GitHub App が PR の書き込み権限を必須にしており、「PR に書き込まない」をプロンプトでしか守れない。GitHub トリガーはレビュアーやチームで絞り込めない。`~/.claude` の設定も読まれない |
| GitHub Actions | 各リポジトリに入れるチームの仕組みになり、結果の出し先が PR コメントになりやすい |
| 結果ページを claude.ai の Artifact にする | 非公開のコードを claude.ai に置くことになり、質問のときにリポジトリ全体も読ませられない |
| 前回レビューした SHA からの差分を渡す | 全体をレビューし直し、前回の結果と見比べれば足りる |
| リポジトリ全体を TCC の対象外に置く | 置き場所を利用者に縛らないため、python3 への許可で済む形にした |

## やらないこと

- PR へのコメント・approve・ラベル付けなどの書き込み
- Slack などへの通知
- 結果ページの共有
